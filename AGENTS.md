## Design-first visual quality for new work (operator scope 2026-11-12)

Apply these principles **only** when the task involves motion graphics, kinetic typography, a visual composition or the opt-in editor UI; do not slow down unrelated maintenance. This is a small addition to the existing product charter, [Issue #5](https://github.com/rayray12zx3-sys/ai-motion-studio/issues/5), [motion registry](.agents/skills/motion-registry/SKILL.md), and independent visual review — **not** a new Skill, renderer, license approval or blanket art direction.

1. **Brief before tool.** Before selecting a rendering method or writing production pixels, identify the real subject/audience, exact text and intended comprehension; specify aspect, safe areas, duration and the causal motion chain (trigger → visual response → consequence). Sketch one compact design direction: primary hierarchy, font roles from the existing authorized font catalog, palette with purpose, composition/negative space, and one justified focal motion. Do not generate unrelated design options or long plans by default.
2. **Purposeful design over template defaults.** Make typography, spacing, contrast and layout decisions specific to the brief. Reject duplicated dark plates, generic purple gradients, uniform rounded cards/shadows, ornamental numbered badges, forced uppercase labels, decorative metadata and repeated fades/slides **when they do not encode real content**. These elements are not universally prohibited if the subject actually calls for them. Adapt frontend-design's web-oriented judgment to video rather than applying web page layouts blindly.
3. **Remove only unnecessary copy.** Avoid redundant subtitles and explanatory labels when hierarchy already communicates the meaning, but never remove specified spoken/subtitle copy, scene narrative, approved text/timing, required safety/license notices, user guidance or error/irreversible-action warnings. For editor UI, name actions by their effect and keep empty/error states actionable.
4. **Protect actual motion.** Reference proven source mechanics through `registry/cli.mjs` when useful. Real easing, anticipation, stagger, continuity, holds and readable settled poses matter more than adding decorative movement. Validate measured Traditional Chinese glyph bounds and collision/safe-area behavior **over time**, including vertical formats; a codec/alpha PASS is not an art PASS.
5. **Design decides; engine implements.** Preserve the approved default JS Canvas + hash-verified FFmpeg runtime and opt-in boundaries. The [2026-11-03 prohibition](docs/NEW-VISUAL-RENDERER-POLICY-2026-11-03.md) on Python/Pillow producing new animation pixels remains in force. Never substitute an easier renderer, simplify a requested mechanism silently, or let this design guidance authorize a different engine/dependency.
6. **Review real moving work.** For any claim of design improvement, inspect an actually decoded, full-speed playable preview against the brief and old baseline using the same copy/aspect/duration. Report concrete gains and defects (read order, font coverage, overlaps, composition diversity, causal timing, safe area, rights, iteration cost), and keep separate `TECH_PASS`, `VISUAL_PREFLIGHT`, `USER_ART_PENDING`, Windows Premiere and distribution-rights statuses. Only the operator may give artistic approval.
7. **No approval inheritance or duplicate infrastructure.** Preserve previously approved exact K-series assets and frozen/rejected art. Do not create another design Skill, CI quality gate, renderer, default output preset or project just to restate these principles. Existing standalone QA gates and [Issue #5](https://github.com/rayray12zx3-sys/ai-motion-studio/issues/5) remain the tracking locations.

**Isolated synthetic design study:** [experiments/design-quality/compare.html](experiments/design-quality/compare.html) contrasts a *fictional generic-card baseline* with a semantics-first notification animation. It uses **browser JavaScript Canvas**, not this repository's locked `@napi-rs/canvas` production renderer; no company materials or proprietary assets are present. Its appearance is an illustration, **not a genuine before/after measurement of historic v6 art**, not an approved template, and not a release/Premiere validation. Future official production work must independently pass the existing renderer, provenance and art gates.

Design inspiration: [Anthropic frontend-design](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md) (web UI guidance; use brief-specific judgment), and [clear interface copy discussion](https://www.aiposthub.com/agents-md-interface-copy/) (do not strip necessary warnings).
